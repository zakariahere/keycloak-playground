Keycloak Playground

One Spring Boot app playing both OAuth2 roles at once: a browser client that logs you in, and an API that accepts bearer tokens.

You are anonymous

This page is permitAll(), which is why you can read it. Everything else redirects you to Keycloak.

Two users are seeded in the realm:

alice / alicerealm role app-user — gets 403 on admin routes
bob / bobrealm roles app-userapp-admin

Start the Authorization Code flow

That link is not a page in this app. It is the trigger Spring Security installs: hitting it builds the authorization request and redirects your browser to Keycloak.

You are signed in

Keycloak authenticated you and this app exchanged the resulting code for tokens.

Try the API from the command line

The /api/** routes are served by a separate, stateless filter chain. Your browser session means nothing to them — they only read bearer tokens.

# 1. No token needed
curl -s http://localhost:8090/api/public

# 2. Same endpoint, protected -> 401
curl -i -s http://localhost:8090/api/me | head -1

# 3. Get a token straight from Keycloak, then retry
TOKEN=$(curl -s -d grant_type=password -d client_id=spring-web \
  -d client_secret=spring-web-secret -d username=bob -d password=bob \
  http://localhost:8180/realms/playground/protocol/openid-connect/token \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')

curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8090/api/admin/report
