08The bug everyone hits

Keycloak writes roles here. Spring reads somewhere else.

// What Keycloak actually emits
{ "realm_access": { "roles": ["app-admin"] } }

// What Spring Security reads by default
{ "scope": "openid profile email" }
//   -> SCOPE_openid, SCOPE_profile, SCOPE_email
//   -> zero ROLE_* authorities
RESULT

hasRole("app-admin") returns false for an obvious admin, and nothing is logged anywhere.

WIRED TWICE, ON PURPOSE
PathHook
APIJwtAuthenticationConverter
reads the access token
LoginGrantedAuthoritiesMapper
reads the ID token

And a Keycloak-side half: roles live in the access token, but oauth2Login only reads the ID token. A protocol mapper closes that gap.

Claim missing → check Keycloak’s mappers. Claim present but rejected → check Spring’s converters.
