03Three lookalike strings

Same base64 gibberish. Three different jobs.

ParameterBindsThe attack it closes
state the callback → your browser session An attacker splicing their login into your session
nonce the ID token → this one request An old or borrowed ID token replayed at your app
code_challenge the code → the client that asked A stolen code being redeemed by anybody else
WHY THEY GET CONFUSED

All three are random per request, all three round-trip, all three are checked on the way back. But they protect different pairs — and dropping any one of them leaves a hole the other two do not cover.

Read them as bindings, not as "security tokens". Each one welds together two things that an attacker would otherwise mix and match.
