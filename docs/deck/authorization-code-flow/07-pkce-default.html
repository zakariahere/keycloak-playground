06Spring Security 7.1

We never enabled PKCE. It was on anyway.

WHAT EVERY TUTORIAL TELLS YOU TO WRITE 
resolver.setAuthorizationRequestCustomizer(
    OAuth2AuthorizationRequestCustomizers.withPkce());

The opt-in customizer exists, and for years it was required for confidential clients. We never called it.

The request still carried code_challenge_method=S256.

WHY IT MATTERED HERE

The spring-web client sets pkce.code.challenge.method: S256, so Keycloak requires a challenge.

Had Spring not sent one, every login since day one would have failed. They didn't — which is the proof, arrived at backwards.

Check the wire before you copy a fix. A tutorial telling you to add withPkce() for a confidential client is describing an older Spring Security.
